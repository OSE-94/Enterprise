# PeoplePulse

PeoplePulse is a Flutter employee self-service app. Firebase Authentication
handles sign-in; Supabase Postgres stores employee profiles, shifts, locations,
and break history.

## Supabase and Firebase setup

The app uses Supabase project `qajmkpqxdptcvnookya` and Firebase project
`enterprise-c71ec`.

1. In Supabase, open **Authentication → Third-Party Auth**, add a Firebase
   integration, and enter Firebase project ID `enterprise-c71ec`.
2. Supabase expects Firebase ID tokens to contain the custom claim
   `role: "authenticated"`. Set it using the Firebase Admin SDK from a trusted
   server environment (never from client code). For an existing user, the
   Firebase Admin SDK operation is:

   ```javascript
   const user = await getAuth().getUser(firebaseUid);
   await getAuth().setCustomUserClaims(firebaseUid, {
     ...user.customClaims,
     role: "authenticated",
   });
   ```

   Import `getAuth` from `firebase-admin/auth` and initialize the Admin SDK
   with trusted server credentials first. Repeat this for each existing user;
   new user accounts also need a trusted onboarding function that sets the
   claim. After the claim is set, refresh the user's ID token or sign out and
   back in.
3. In the Supabase SQL Editor, run the complete migration in
   `supabase/migrations/20261015190000_attendance.sql`.
4. In **Project Settings → API Keys**, copy the project's publishable key
   (`sb_publishable_...`). This client key is intended for Flutter apps; never
   use a `service_role` or secret key in the app.
5. Run the app from PowerShell, setting the publishable key from the dashboard:

   ```powershell
   $env:SUPABASE_PUBLISHABLE_KEY = "sb_publishable_..."
   flutter pub get
   flutter run -d edge `
     --dart-define=SUPABASE_URL=https://qajmkpqxdptcvnookya.supabase.co `
     "--dart-define=SUPABASE_PUBLISHABLE_KEY=$env:SUPABASE_PUBLISHABLE_KEY"
   ```

Employees can register with Firebase Authentication. On first use, the app
creates their employee profile in Supabase. To grant administrator access,
use the Supabase SQL Editor with the employee's Firebase UID:

```sql
update public.employee_profiles
set role = 'admin'
where uid = '<firebase-auth-uid>';
```

Only a trusted administrator should run that statement. Employee clients cannot
change their role. Supabase RLS limits employees to their own data and allows
admins to read team attendance. Clock-in/out timestamps are generated by
Postgres; the app captures device coordinates only for those two events.
Break start/end times are also recorded. No continuous location tracking or
worksite geofence is used.

If you previously registered before this setup, the Firebase account may
already exist. Sign in with that account after configuring Supabase.

Time-off requests, balances, and company updates are still sample data from
`HrService`.

## Run checks

```powershell
flutter analyze
flutter test
flutter build web
```

## Project structure

- `lib/models/` — employee, attendance, leave, and announcement models
- `lib/providers/` — app and attendance state
- `lib/services/` — Firebase Authentication, Supabase, and GPS operations
- `lib/screens/` — dashboard, time clock, admin attendance, time off, updates,
  profile, and sign-in
- `lib/widgets/` — shared UI components
- `supabase/migrations/` — schema, attendance RPCs, Realtime, and RLS policies
- `web/` — Flutter web entry point and assets
